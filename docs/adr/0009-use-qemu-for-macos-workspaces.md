# Use QEMU for macOS Workspaces

The initial macOS integration uses QEMU/KVM for nested `aarch64-linux` Workspaces, with Linux 6.12 LTS pinned in both the Seter Host and Workspace, because the physical-Mac gate and [equivalence review](../macos-qemu-equivalence.md) demonstrated the required lifecycle, isolation, storage, networking, and host-policy contracts while Cloud Hypervisor did not boot the workload reliably. Cloud Hypervisor remains the native-Linux default; QEMU brings a larger device-model attack surface and a larger closure, so the macOS Runner retains Seter's dedicated account, systemd device and filesystem restrictions, cgroup limits, exact TAP binding, read-only Store View, host-owned policy enforcement, and the [fw_cfg Workspace SSH Identity transport](./0010-use-fw-cfg-for-macos-workspace-ssh-identity.md).
